# pi-codegraph integration research

Primary-source snapshot: `vndv/pi-codegraph` at [`f0d3a78`](https://github.com/vndv/pi-codegraph/tree/f0d3a783c2be490d2f7d2b0e176b58d1e08d7cb3) and upstream CodeGraph at [`572d22b`](https://github.com/colbymchenry/codegraph/tree/572d22bfbe82602080e457bec655f72e3314f9ef).

## Package entrypoint and runtime

- `@vndv/pi-codegraph` v0.1.10 is a Pi package via `"pi": { "extensions": ["./extensions"] }`; its explicit subpath exports both resolve to `./extensions/codegraph.ts`. Pi discovers that directory and loads the file's default `codegraphExtension(pi)` export. [[manifest](https://github.com/vndv/pi-codegraph/blob/f0d3a783c2be490d2f7d2b0e176b58d1e08d7cb3/package.json)] [[extension](https://github.com/vndv/pi-codegraph/blob/f0d3a783c2be490d2f7d2b0e176b58d1e08d7cb3/extensions/codegraph.ts)]
- The published package has **no ordinary npm dependencies**. `@earendil-works/pi-coding-agent` and `typebox` are peers supplied by Pi; Node `>=22.19.0` is required. `@colbymchenry/codegraph` is only a dev dependency (`^1.0.1`), so the extension does **not** ship the runtime CLI. At runtime it requires an executable literally named `codegraph` on `PATH`. [[manifest](https://github.com/vndv/pi-codegraph/blob/f0d3a783c2be490d2f7d2b0e176b58d1e08d7cb3/package.json)]
- If Matty bundles upstream instead, current CodeGraph 1.5.0 exposes CLI bin `codegraph` and library main `dist/index.js`; its npm package carries JS dependencies plus per-platform optional binary packages. The embedded API requires Node 22.5+, which Pi's 22.19 floor satisfies. [[upstream package](https://github.com/colbymchenry/codegraph/blob/572d22bfbe82602080e457bec655f72e3314f9ef/package.json)] [[API docs](https://github.com/colbymchenry/codegraph/blob/572d22bfbe82602080e457bec655f72e3314f9ef/site/src/content/docs/reference/api.md)]

## Exact initialization and detection

- CLI: `codegraph init [path]`. It always creates and fully indexes the project; `-i/--index` is retained as a deprecated **no-op**. Internally the CLI calls `CodeGraph.init(projectPath, { index: false })`, then `cg.indexAll(...)`, then destroys the instance. [[CLI source](https://github.com/colbymchenry/codegraph/blob/572d22bfbe82602080e457bec655f72e3314f9ef/src/bin/codegraph.ts)] [[CLI reference](https://github.com/colbymchenry/codegraph/blob/572d22bfbe82602080e457bec655f72e3314f9ef/site/src/content/docs/reference/cli.md)]
- Programmatic one-step equivalent: `const cg = await CodeGraph.init(projectRoot, { index: true }); try { /* ready */ } finally { cg.close(); }`. Important: `CodeGraph.init(projectRoot)` alone creates the DB but does **not** index because `options.index` defaults false. [[API implementation](https://github.com/colbymchenry/codegraph/blob/572d22bfbe82602080e457bec655f72e3314f9ef/src/index.ts)]
- Exact initialized predicate: the configured data directory exists as a directory **and contains `codegraph.db`**. A bare `.codegraph/` is not initialized. The directory defaults to `.codegraph`, but `CODEGRAPH_DIR=<single-directory-name>` overrides it. `findNearestCodeGraphRoot()` walks ancestors using that same predicate; MCP uses nearest-root detection, so an indexed ancestor already serves a nested working directory. [[directory source](https://github.com/colbymchenry/codegraph/blob/572d22bfbe82602080e457bec655f72e3314f9ef/src/directory.ts)]

### Files created

Normal first initialization creates:

1. `<root>/.codegraph/` (or the `CODEGRAPH_DIR` override),
2. `<root>/.codegraph/.gitignore` containing a wildcard rule that ignores everything else in the data directory, and
3. `<root>/.codegraph/codegraph.db`, initialized with the SQLite schema and then populated. [[directory source](https://github.com/colbymchenry/codegraph/blob/572d22bfbe82602080e457bec655f72e3314f9ef/src/directory.ts)] [[database source](https://github.com/colbymchenry/codegraph/blob/572d22bfbe82602080e457bec655f72e3314f9ef/src/db/index.ts)]

Indexing/runtime can additionally create transient `codegraph.db-wal`, `codegraph.db-shm`, and `codegraph.lock`; `errors.log` is written only when indexing reports file errors. An interactive init can conditionally update root `codegraph.json` if the user opts ignored nested repositories in, and can offer Git hooks when live watching is disabled. MCP daemon startup later adds `daemon.pid`, `daemon.log`, and usually `daemon.sock` (socket may fall back to a hashed temp path), plus a discovery record under `~/.codegraph/daemons/`. [[CLI source](https://github.com/colbymchenry/codegraph/blob/572d22bfbe82602080e457bec655f72e3314f9ef/src/bin/codegraph.ts)] [[daemon paths](https://github.com/colbymchenry/codegraph/blob/572d22bfbe82602080e457bec655f72e3314f9ef/src/mcp/daemon-paths.ts)] [[registry](https://github.com/colbymchenry/codegraph/blob/572d22bfbe82602080e457bec655f72e3314f9ef/src/mcp/daemon-registry.ts)]

## Daemon and Pi-call lifecycle

- Every Pi tool execution resolves/validates an absolute project directory, spawns `codegraph serve --mcp --path <project>`, sends MCP `initialize` (`2024-11-05`, root URI/workspace folder) then `initialized`, makes one `tools/call`, and kills the spawned child in `finally`. Abort also kills it; the whole session has a 20-second timeout. There is no persistent child owned by the Pi extension. [[extension](https://github.com/vndv/pi-codegraph/blob/f0d3a783c2be490d2f7d2b0e176b58d1e08d7cb3/extensions/codegraph.ts)]
- For an indexed project, that child is normally a thin stdio-to-socket **proxy**. The first proxy starts one detached daemon per canonical project root; all proxies share one engine, SQLite connection, and watcher. Killing Pi's per-call proxy merely disconnects that client. After the last client disconnects, the daemon lingers for `CODEGRAPH_DAEMON_IDLE_TIMEOUT_MS` (default 300,000 ms), then removes its pid/socket/registry artifacts and exits. It also handles SIGTERM/SIGINT and dead-client cleanup. [[MCP mode selection](https://github.com/colbymchenry/codegraph/blob/572d22bfbe82602080e457bec655f72e3314f9ef/src/mcp/index.ts)] [[daemon](https://github.com/colbymchenry/codegraph/blob/572d22bfbe82602080e457bec655f72e3314f9ef/src/mcp/daemon.ts)]
- `CODEGRAPH_NO_DAEMON=1`, no reachable initialized root, daemon failure, or daemon version mismatch causes direct in-process MCP fallback. The watcher performs debounced sync (default 2s) and connect-time catch-up. [[MCP source](https://github.com/colbymchenry/codegraph/blob/572d22bfbe82602080e457bec655f72e3314f9ef/src/mcp/index.ts)] [[indexing guide](https://github.com/colbymchenry/codegraph/blob/572d22bfbe82602080e457bec655f72e3314f9ef/site/src/content/docs/guides/indexing.md)]

## Existing hooks/surfaces

- Pi hook: only `before_agent_start`, which appends CodeGraph usage guidance to the system prompt. The extension also registers eight native tools: `codegraph_search`, `node`, `files`, `callers`, `callees`, `impact`, `explore`, and `status`. It has no Pi session-start/session-end/init hook. [[extension](https://github.com/vndv/pi-codegraph/blob/f0d3a783c2be490d2f7d2b0e176b58d1e08d7cb3/extensions/codegraph.ts)]
- Upstream non-Pi integrations: an optional Claude `UserPromptSubmit` front-load hook, and optional marker-fenced Git `post-commit`, `post-merge`, and `post-checkout` hooks that background `codegraph sync` when watching is unavailable. These are installer features, not Pi hooks. [[installer](https://github.com/colbymchenry/codegraph/blob/572d22bfbe82602080e457bec655f72e3314f9ef/src/installer/index.ts)] [[Git hooks](https://github.com/colbymchenry/codegraph/blob/572d22bfbe82602080e457bec655f72e3314f9ef/src/sync/git-hooks.ts)]

## Recommended Matty integration

1. Make `@colbymchenry/codegraph` a **runtime** dependency (pin/test a version), not merely a dev dependency. Do not assume Pi's process `PATH` includes Matty's local `node_modules/.bin`; either resolve the bundled CLI shim explicitly or prepend its bin directory before using the unchanged pi-codegraph extension.
2. At the earliest project-aware lifecycle point, single-flight per canonical root and test for an initialized root using upstream `CodeGraph.isInitialized(root)` / `findNearestCodeGraphRoot(root)`. If avoiding the API, reproduce the exact check: `<dir>/<CODEGRAPH_DIR || '.codegraph'>/codegraph.db`. Use nearest-root detection to avoid creating a redundant nested graph; use exact-root detection only if Matty intentionally requires a separate index at that root.
3. Only when absent, prefer the bundled API for automation: `CodeGraph.init(root, { index: true })`, then `close()`. It avoids the CLI's interactive optional prompts and does not install agent/Git hooks. If invoking the CLI, use exactly `codegraph init <absolute-root>`; do not add `-i`.
4. Keep initialization out of pi-codegraph's existing `before_agent_start` guidance hook unless Matty guarantees it runs once: indexing can be long, and that hook can run repeatedly. Guard concurrent sessions/processes with Matty-side single-flight and re-check after acquiring it. On failure, leave normal Pi tools usable and report the initialization error; never repeatedly re-init when `codegraph.db` already exists.
5. No daemon orchestration is needed after init. The existing `serve --mcp --path` calls automatically converge on the shared project daemon and its watcher.

One compatibility caveat: current upstream MCP lists only `codegraph_explore` by default, although all eight remain callable; pi-codegraph directly registers and calls all eight, so retain its tool layer or set `CODEGRAPH_MCP_TOOLS` if switching to upstream tool discovery. [[upstream MCP docs](https://github.com/colbymchenry/codegraph/blob/572d22bfbe82602080e457bec655f72e3314f9ef/site/src/content/docs/reference/mcp-server.md)]
