# Manage interactive Child Sessions over isolated Pi RPC

Matty will replace its single-response child runtime with one final architecture: each Delegated Task has stable identity and a Child Session executed through bounded, isolated `pi --mode rpc` Child Executions. Pi's JSONL session is the transcript source in a minimal Matty-owned store; settled processes exit rather than forming an idle fleet. Capability Contracts, guards, atomic groups, and Single Writer govern every interaction. Candidate Results may change only before the Delegation freezes, while later work becomes a preflighted Continuation instead of rewriting parent history. Matty deliberately provides no in-process `AgentSession`, print fallback, compatibility layer, or migration for the runtime and schemas this design replaces.
